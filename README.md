# 사회복지현장 AI 역량 시험

사회복지 현장 취업 준비생을 위한 **AI 활용 역량 평가 웹앱**입니다. 종합사회복지관·지역아동센터·
요양원·정신건강복지센터 등 실제 사회복지 현장 32곳 중 하나를 선택하면, **AI가 그 자리에서
그 현장에 맞는 시험 문항 3개를 새로 출제**합니다. 문항을 미리 고정해두지 않기 때문에 같은
현장을 다시 선택해도 매번 다른 사례가 나옵니다. 응시자는 오른쪽 AI 어시스트와 실제로 대화하며
문제를 해결하고, 제출하면 AI가 곧바로 채점합니다.

## 구성

- 시작 화면: 이름/소속 입력 + 32개 현장 중 선택 — 종합사회복지관·지역아동센터·요양원·
  재가복지센터·방문간호센터·정신건강복지센터·가족센터·자활센터·병원(의료사회복지)·
  학교(학교복지)·직업재활·공기업(사회복지)·가정위탁센터·사회복지공무원·키움센터·
  다함께돌봄센터·아동보호전문기관·독거노인종합지원센터·사회복지사협회·지역사회보장협의체·
  사회복지협의회·청소년쉼터·청소년수련관·청소년문화의집·청소년상담복지센터·
  장애인주간이용시설·청소년활동진흥원·청년센터·성폭력피해자쉼터·청소년자립지원관·
  느린학습자지원센터·발달장애인지원센터
- 현장을 선택하면 AI가 그 자리에서 문항 3개를 출제 — 실전 사례형 2개 + **문서 자동화
  맞춤지침 설계 1개** (그 현장에서 실제 쓰는 문서 예시를 AI가 만들고, 그 문서를 자동
  작성하도록 하는 커스텀 지침을 응시자가 직접 설계하는 문항)
- 왼쪽/가운데: 문항 사례, 과업, 최종 답안 작성, 타이머(영역당 최대 30분), 문항 이동
- 상단 우측: 눈에 잘 띄는 **제출하기** 버튼, 채점 없이 중단하는 **시험 종료** 버튼,
  그리고 시험 중 다른 화면으로 이동하면 뜨는 **이탈 감지** 배지 (아래 7번 참고)
- 오른쪽: 실제 AI와 대화할 수 있는 채팅 패널 (무료 AI API 연동, 응시자 1인당 최대 20회)
- 제출 후: **AI가 실제로 채점**하여 **100점 만점 총점 + 등급(A+~F)**을 바로 보여줍니다.
  문항마다 5개 역량 기준(문제해결능력·창의적 사고·비판적 사고·비식별화 준수·프롬프트 활용
  역량)으로 세분화해서 0~5점씩 채점하고, 역량별 합산 점수를 **막대그래프**로 한눈에 비교해
  보여줍니다. 각 기준별 점수와 채점 이유, 답안/채점결과/AI 대화기록은 다운로드(.txt)할 수
  있습니다.

## 1. 설치

```bash
npm install
cp .env.example .env
```

## 2. 무료 AI API 키 발급 (택 1)

카드 등록 없이 무료로 사용 가능한 두 가지 중 하나를 선택하세요.

### 옵션 A. Google Gemini (기본값, 추천)
1. https://aistudio.google.com/apikey 접속 후 구글 계정으로 로그인
2. "Create API key" 클릭 → 키 복사
3. `.env` 파일에 입력:
   ```
   AI_PROVIDER=gemini
   GEMINI_API_KEY=발급받은키
   ```

**무료 티어 한도에 대해 꼭 알아둘 점**

Gemini 무료 티어의 일일 요청 한도는 **모델별로 따로** 계산됩니다
(`quotaId: GenerateRequestsPerDayPerProjectPerModel-FreeTier`). 이 프로젝트에서 실측한 값은
모델당 하루 20회였습니다(문서상 수치와 다를 수 있으니 본인 키로 확인하세요).

응시자 한 명이 시험을 한 번 치르면
**출제 1회 + AI 대화 최대 20회 + 채점 3회 = 최대 24회**를 사용합니다. 세 작업이 같은 모델을
쓰면 대화를 많이 한 응시자는 정작 마지막 **채점에서 한도가 걸려 실패**합니다.

그래서 `providers/gemini.js`는 작업마다 다른 모델을 1순위로 쓰고, 한도 초과(429)나
과부하(503)가 나면 다음 모델로 자동 전환합니다.

| 작업 | 1순위 모델 | 호출 수/응시자 |
|---|---|---|
| 채점 | `gemini-3.5-flash` (판단 품질 우선) | 3회 |
| 대화 | `gemini-3.1-flash-lite` (호출 수가 가장 많음) | 최대 20회 |
| 출제 | `gemini-2.5-flash` | 1회 |

전환 순서: 위 1순위 → `gemini-3.5-flash` → `gemini-2.5-flash` → `gemini-3.1-flash-lite` →
`gemini-2.5-flash-lite`. 모델을 직접 지정하려면 `GEMINI_GRADE_MODEL`,
`GEMINI_CHAT_MODEL`, `GEMINI_GENERATE_MODEL`에 쉼표로 구분해 넣으면 됩니다.

> `GEMINI_MODEL`을 설정하면 세 작업 모두 그 모델부터 시도합니다(예전 설정 호환용).
> 작업별 분산 효과가 사라지므로 **비워두기를 권장**하며, 설정되어 있으면 서버 시작 시 경고를 띄웁니다.

### 옵션 B. Groq (Gemini 대체용, 응답 속도 빠름)
1. https://console.groq.com/keys 접속 후 로그인
2. "Create API Key" → 키 복사
3. `.env` 파일에 입력:
   ```
   AI_PROVIDER=groq
   GROQ_API_KEY=발급받은키
   ```

## 4. 주요 설정 (.env)

| 변수 | 설명 | 기본값 |
|---|---|---|
| `AI_PROVIDER` | `gemini` 또는 `groq` | `gemini` |
| `EXAM_MINUTES_PER_QUESTION` | 문항 1개당 제한 시간(분). 실제 시험 시간 = 선택 영역의 문항 수 × 이 값 | `12` |
| `EXAM_MAX_MINUTES` | 영역 하나의 시험 시간이 아무리 길어도 넘지 않는 최대값(분) | `30` |
| `MAX_AI_MESSAGES` | 응시자 1인당 전체 시험에서 AI에게 보낼 수 있는 최대 메시지 수 | `20` |
| `PORT` | 서버 포트 | `3000` |
| `GEMINI_GRADE_MODEL` | 채점에 쓸 모델(쉼표로 여러 개, 앞에서부터 시도) | `gemini-3.5-flash` |
| `GEMINI_CHAT_MODEL` | AI 대화에 쓸 모델 | `gemini-3.1-flash-lite` |
| `GEMINI_GENERATE_MODEL` | 출제에 쓸 모델 | `gemini-2.5-flash` |
| `GEMINI_MODEL` | (구 설정) 세 작업 모두의 1순위. 비워두는 편이 한도를 오래 씁니다 | 없음 |

## 5. 현장 추가·수정 (문항은 손으로 쓰지 않습니다)

`data/domains.js`에 현장(기관/직무) 프로필이 32개 들어 있습니다. 문항을 미리 써두는 대신,
이 프로필 정보를 바탕으로 시험 시작 시점에 AI가 문항 3개를 즉석 출제합니다(`/api/generate-questions`,
`providers/*.js`의 `generateQuestions`). 각 프로필은 다음 필드로 구성됩니다.

| 필드 | 설명 |
|---|---|
| `key` | 내부 식별자(영문). API에서 현장을 지정할 때 사용 |
| `label` | 화면에 보이는 현장 이름 |
| `color` | 선택 화면 칩 색상 |
| `brief` | 이 현장이 어떤 곳인지, 주로 어떤 위기·갈등을 다루는지 — 출제 AI에게 주는 배경 정보 |
| `docHint` | 이 현장에서 실제 반복 작성하는 문서 종류 — 문서 자동화 문항(문항 3) 출제에 활용 |
| `persona` | 채팅 코치 AI에게 주는 페르소나 지시문. 현장마다 1개이며, 출제되는 문항이 매번 달라져도 유지됨 |

새 현장을 추가하려면 `data/domains.js` 배열에 같은 형식으로 객체를 추가하면 되고, 선택 화면의
현장 버튼은 이 배열을 기준으로 자동 생성됩니다(별도 코드 수정 불필요). `brief`/`docHint`를
구체적으로 쓸수록 출제되는 사례의 현실성이 높아집니다.

## 6. 채점 방식

제출(`/api/submit`) 시 문항마다 AI(Gemini/Groq)에게 사례·과업·응시자 최종 답안·(해당 문항의)
AI 대화 기록을 전달해 채점을 요청합니다. 모든 문항은 항상 동일한 **5개 역량 기준**
(`data/domains.js`의 `COMPETENCIES`)으로 채점되어, 현장·문항이 매번 달라져도 역량별 결과를
하나의 막대그래프로 합산·비교할 수 있습니다.

| 역량 | 무엇을 보는가 |
|---|---|
| 문제해결능력 | 핵심 문제를 짚고 실행 가능하고 구체적인 해결책을 제시했는가 |
| 창의적 사고 | 틀에 박히지 않은, 이 사례에 맞는 새로운 접근을 시도했는가 |
| 비판적 사고 | AI 제안을 무비판적으로 받아들이지 않고 현장 전문성으로 검증·보완했는가 |
| 비식별화 준수 | 답안에 실명·주민등록번호·주소·전화번호 등을 그대로 노출하지 않았는가 |
| 프롬프트 활용 역량 | AI와의 대화에서 맥락을 명확히 전달하고 효과적으로 질문했는가 (AI와 대화하지 않았다면 0점) |

각 기준을 0~5점으로 채점합니다(문항당 최대 25점). 문항 수만큼 합산해 총점을 **100점
만점으로 환산**하고, 아래 기준으로 등급을 매깁니다.

| 등급 | 백분율 |
|---|---|
| A+ | 95점 이상 |
| A | 90~94점 |
| B+ | 85~89점 |
| B | 80~84점 |
| C+ | 75~79점 |
| C | 70~74점 |
| D+ | 65~69점 |
| D | 60~64점 |
| F | 60점 미만 |

### 역량마다 남기는 피드백

응시자가 점수만 보고 끝나지 않도록, 역량마다 아래 세 가지를 함께 생성합니다.

| 항목 | 내용 |
|---|---|
| 확인된 내용 | 답안에서 실제로 확인된 부분과 잘한 점 (답안 문구를 인용) |
| 미흡한 점 | 어떤 항목이 빠졌는지, 어느 서술이 왜 불충분해서 점수가 깎였는지 |
| 이렇게 보완하세요 | 다음에 답안에 넣을 만한 문장·항목을 예시로 제시 |

문항마다 "가장 낮은 역량이 무엇이고 왜 낮은지, 무엇부터 보완해야 하는지"를 담은 **총평**도
함께 표시되며, 0~5점은 화면에서 `우수 / 양호 / 보통 / 미흡 / 해당 없음` 구간 라벨로 함께
보여줍니다. 이 내용은 결과 화면과 다운로드되는 `.txt` 보고서에 모두 들어갑니다.

### 채점이 실패한 경우

답안을 작성하지 않은 문항은 AI 호출 없이 모든 기준 0점으로 처리됩니다.

채점 API 호출이 실패하면 **1.2초 간격으로 3회까지 재시도**하고, 그래도 실패하면 해당 문항을
0점으로 깎는 대신 **"채점 보류"로 표시하고 총점 계산에서 제외**합니다(만점도 함께 빠집니다).
응시자 잘못이 아닌 이유로 등급이 떨어지지 않게 하기 위해서입니다. 결과 화면 상단에도
몇 개 문항이 제외되었는지 안내가 뜨고, 해당 문항은 `.txt` 보고서를 평가자에게 전달해
수동 채점하면 됩니다.

등급 기준선(`server.js`의 `scoreToGrade`)은 필요에 맞게 조정할 수 있습니다.

## 7. 시험 중 이탈 감시 (부정행위 억제)

**중요: 웹페이지가 브라우저 탭을 못 닫게 하거나, 다른 탭에서 검색하는 것을 막는 것은
기술적으로 불가능합니다.** (브라우저 보안 정책이며, 가능하다면 그게 더 큰 문제입니다.)
그래서 이 앱은 "차단"이 아니라 **억제 + 기록** 방식으로 동작합니다.

- **나가기 경고**: 시험 중 탭을 닫거나 새로고침·뒤로가기를 시도하면 브라우저 기본 확인창이
  뜹니다(`beforeunload`). 실수로 나가는 것은 막아주지만, 의도적으로 "나가기"를 누르면 나갈 수
  있습니다.
- **전체화면**: 시험 시작 시 전체화면을 요청해, 다른 창으로 넘어가려면 의도적인 행동이
  필요하게 만듭니다.
- **이탈 감지·기록**: 다른 탭·다른 앱으로 이동하거나 창을 최소화하면(`visibilitychange`)
  횟수가 집계되어 상단에 **"이탈 감지 N회"** 배지와 경고 배너가 표시되고, 제출 시
  `proctor: { leaveCount, fullscreenExitCount }`로 함께 저장되어 평가자가 확인할 수 있습니다.
  점수에는 자동 반영하지 않습니다(평가자 판단에 맡김).
- **시험 종료 버튼**: 채점 없이 시험을 중단하는 별도 버튼입니다. 확인 후 나가기 잠금을 해제하고
  처음 화면으로 돌아갑니다(작성 중이던 답안은 저장되지 않음).

완전한 감독이 필요하다면 현장 감독, 또는 브라우저 자체를 잠그는 전용 시험 프로그램
(예: 키오스크 모드 배포)을 병행하셔야 합니다.

## 8. 제출 데이터

응시자가 제출하면 `data/submissions/`에 이름+타임스탬프로 JSON 파일이 저장됩니다
(답안 전문 + AI 대화 기록 + 채점 결과 + 이탈 기록 포함, 평가자가 검토용으로 확인 가능).
이 폴더는 `.gitignore`에 포함되어 있어 커밋되지 않습니다.

## 9. 배포 시 참고

- API 키가 서버에서만 사용되므로(브라우저에 노출되지 않음) 안전합니다.
- Render, Railway, Fly.io 등 상시 실행형 Node.js 호스팅은 `server.js`를 그대로 배포하면 됩니다.
- 배포 시 환경변수(`GEMINI_API_KEY` 등)를 호스팅 서비스의 환경변수 설정에 등록하세요.
- 문항을 매번 새로 출제하는 구조라 응시자 1명당 AI 호출이 예전보다 많습니다(출제 1회 +
  채팅 최대 20회 + 채점 3회). 무료 티어의 분당/일당 한도에 걸리면 `/api/generate-questions`가
  한 번 자동 재시도한 뒤에도 실패할 수 있는데, 이때는 응시자 화면에 오류 메시지와
  **다시 시도** 버튼이 뜨므로 잠시 후 다시 누르면 됩니다.
- 기본 모델은 `gemini-2.5-flash-lite`입니다. `gemini-2.5-flash`는 실제 테스트 중 확인한 바로
  프로젝트당 **하루 20회**로 무료 한도가 꽤 낮게 잡혀 있는 경우가 있어(계정/프로젝트에 따라
  다를 수 있음), 모델별로 한도가 별도로 관리되는 `flash-lite`를 기본값으로 씁니다. 실제 한도는
  https://aistudio.google.com/apikey 사용량 화면에서 확인할 수 있습니다. 그래도 응시 인원이
  많아 한도에 자주 걸린다면 `AI_PROVIDER=groq`로 전환하는 것을 고려하세요.

### Vercel 배포

Vercel은 서버리스 환경이라 `app.listen()`으로 상시 실행되는 서버를 그대로 인식하지 못합니다.
이를 위해 `api/index.js`(서버리스 함수 진입점)와 `vercel.json`(모든 요청을 그 함수로 라우팅)을
이미 포함해 두었으니 별도 설정 없이 배포하면 됩니다.

1. Vercel 프로젝트 생성 후 이 저장소를 연결
2. **Project Settings → Environment Variables**에서 아래 값을 등록 (Production/Preview 모두)
   ```
   AI_PROVIDER=gemini
   GEMINI_API_KEY=발급받은키
   ```
   `.env` 파일은 로컬 전용이며 Vercel에는 올라가지 않으므로, 반드시 대시보드에서 직접 등록해야 합니다.
3. 환경변수를 등록/수정한 뒤에는 **Redeploy**를 한 번 더 실행해야 반영됩니다.
   - 예전에 `GEMINI_MODEL`을 등록해 두었다면 **삭제**하세요. 남아 있으면 대화·출제·채점이
     모두 같은 모델의 하루 한도를 나눠 쓰게 되어, 대화를 많이 한 응시자의 채점이 실패할 수
     있습니다(§2 참고).
4. 참고: 서버리스 특성상
   - `/api/submit` 제출 기록(`data/submissions/`)은 파일로 저장되지 않습니다(읽기 전용 파일시스템). 필요하면 추후 DB(Vercel KV, Supabase 등) 연동을 고려하세요.
   - 응시자별 "AI 대화 가능 횟수" 카운트는 인스턴스별 메모리에 저장되어 정확히 전역으로 합산되지 않을 수 있습니다(교육/내부용으로는 충분한 수준).
